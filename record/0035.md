# Record 0035

The TypeScript mirror of the gate is deleted, and the gate now fails closed.

`evalGateTs` reimplemented `Vps.decideVerdict` by hand — supersession, prefix scoping, the
record-count test — and ruled whenever `leanAvailable()` was false. Nothing proved the two
agreed. ASSESSMENT.md names that object as the disease the restart refused: "a separate formal
model must be kept in correspondence with the implementation — which is precisely a new
watcher watching a watcher." It had been reintroduced here, and it was worse than a watcher,
because it was fail-OPEN wearing the costume of a fallback: an unproved copy quietly deciding
constitutional questions whenever the toolchain was missing.

It is gone. Without the kernel the gate raises rather than rules. A jurisdiction whose kernel
cannot be consulted has not allowed a change; it has failed to judge it (LEARNINGS #17).

**Behaviour change, recorded plainly:** a commit on a machine without the pinned toolchain is
now refused rather than silently permitted. That is the intended direction.

Also ported a safety fix that existed in only one of the two copies of this file: a denial
naming no instrument is now an internal error, not a refusal. `every_deny_names_its_law` is a
theorem, so reaching that branch with nothing cited means the evaluation broke — and this
repository was, until now, reporting that breakage as constitutional law. The fix was written
in the court's copy hours earlier and never reached this one.

That divergence is the argument for consolidation, already realised rather than predicted: of
twelve shared modules, eight had drifted, and the one that drifted in a safety-relevant
direction was this file.

Housekeeping: `lean/Vjs/GateEval.lean` is untracked. It is the gate's own scratch file,
rewritten on every run including the pre-commit hook's, and its ignore pattern went stale when
the directory was renamed — so the gate began denying commits over its own working notes. The
pattern is now `lean/*/GateEval*.lean`, which survives the next rename.
