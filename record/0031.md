# Record 0031

Citator corruption: found, repaired, and made detectable.

`lookup(questionKey)` reads `.justice/INDEX.md` to decide whether a question has already
been answered. That table is what res judicata *is* in practice.

An earlier mechanical refactor in this session converted module-level path constants into
functions and rewrote every bare `INDEX` token to `INDEX()`. One of those tokens was inside
a string literal: `justice("INDEX.md")` became `justice("INDEX().md")`. Reader and writer
therefore agreed on the wrong filename, so nothing failed, nothing warned, and a second
citator quietly accumulated beside the real one.

Effect while it lasted: rulings [2026] VPS 6–21 were invisible to `lookup`, so any question
they had settled was open to being litigated again — and could have been answered
differently by a fresh bench, while `res_judicata` continued to compile. The theorem is
about the memo table agreeing with the gate; it says nothing about the table being the one
the system is actually reading.

No wrong ruling resulted. The eight rulings filed while it was broken (VPS 22–29) were all
on genuinely new keys — family-scoped model shapes and fresh interpret hashes — so no
settled question was re-decided. That is luck, not design.

Repair: the literal is corrected, the orphaned rows merged back in citation order, the stray
file deleted, and the citator now holds 24 rows for 24 rulings.

The lesson is the test, not the fix. Consistency between two wrong things is undetectable
from inside either of them, so `test/citator.test.ts` asserts the invariant from outside:
every ruling in the book has a row, every row names a judgment that exists, no row is an
orphan, and there is exactly one citator file. Only a cross-check between two independently
maintained artefacts could have caught this, and now one does.
