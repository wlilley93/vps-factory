# Record 0025

Scope revision, taken deliberately rather than quietly.

FOUNDRY-PLAN §20 defers "web dashboard" and multi-case views to v2, and §15.5.1 says any
UI beyond the single sign-off page is a v2 matter. A read-only Docket now ships anyway,
authorised by the Principal. The reasoning for allowing it without weakening §15.5.1: the
rule exists to stop the S4 gate growing into a product, and this is not the gate. It has
zero write endpoints, its import graph cannot reach a writer, and `review --web` is
unchanged — still one page, one write endpoint, still the only route past S4.

CLAUDE.md gains two rules, both enforced by tests rather than convention:

5f — no daemon, no watcher, no auto-resume. The pipeline is status-driven, so resuming a
parked run is re-invocation. A resident process that resumes work automatically is one
flag away from one that approves work automatically, and that flag will be proposed.

5g — the Docket is read-only and is not the gate. No POST handler, no approve affordance,
no control that resembles one.

README deviations 1, 2 and 6 are retired (see record/0018.md for 1 and 2). Deviations 7
and 8 are added, recording this scope change and the headless flags §15.2 specified but
never shipped.

Not done, and named rather than left implied: the §20 capability set — richer IR types,
general theorems over all instances, brownfield intake. Each needs its own plan revision
and ruling, and the second carries a Mathlib decision that must not arrive as a side
effect.
